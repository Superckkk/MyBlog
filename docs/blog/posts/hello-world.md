# 开篇：为什么又想起来写博客

这是占位文章，用来演示博客插件的排版效果。真正开始写的时候把这篇删掉就行。

搭这个站点的起因很俗：某个下午调一个诡异的并发问题，花了三个小时，
最后发现两年前自己就踩过一模一样的坑，当时的结论写在某个聊天记录的角落里，
早就翻不出来了。

<!-- more -->

## 之前为什么不写

试过好几次，都没坚持下来。复盘一下，原因大概是这几个：

1. **一开始就想写"完整的教程"。** 一篇讲 asyncio 的文章，光大纲就列了十几条，
   写了两千字发现还在讲背景，然后就搁置了。
2. **发布流程太重。** 之前用过某个需要登录后台、上传图片、点发布的方案，
   写东西的冲动一般持续不到走完这套流程。
3. **怕写错。** 总觉得自己理解得还不够深，等搞明白了再写——结果永远没搞明白。

## 这次打算怎么改

- **只写自己真的用过的。** 不写"XX 入门教程"，写"我在这上面栽过什么跟头"。
- **写完就发。** 站点是纯静态的，本地 `mkdocs build` 一下，推上去就完事。
  图片直接放仓库里，不用传图床。
- **允许自己写错。** 内容有问题就在评论或者 issue 里改，
  留着错误的版本反而能看出认知是怎么变的。

## 关于工具

这个站点用 MkDocs + Material 搭，源文件全是 Markdown，
放在 git 仓库里，改起来和写代码没什么区别。

字体用了[霞鹜文楷](https://github.com/lxgw/LxgwWenKai)，
楷体读长文比黑体舒服一些，代价是字重少、英文排版一般。
具体怎么接进来的写在[另一篇](mkdocs-material-blog-setup.md)里了。
